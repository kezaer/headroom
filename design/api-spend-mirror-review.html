Headroom · PR #22 · Design review

API Spend Mirror — visual review & proposals

A critique of the shipped iPhone tile and widget spend treatments, with concrete proposals. The guiding principle throughout: quota usage stays primary; spend is a quiet secondary mirror. The Mac stays the source of truth — nothing here adds a control to iOS.

01

The three calls

Decisive answers to the open questions, then the mocks that back them up.

Should API spend appear in the medium widget, or only the app + large widgets?
Keep it on medium
The medium widget is the one people actually place on a Home Screen — pulling spend from it hides the feature for most users. But the current strip floats as a peer line. Fix the hierarchy, don't remove the data: merge spend into the freshness row, hairline-separated, so quota clearly wins.
Does the iPhone API Spend tile feel native beside the quota cards?
Close — dial it down
Same tile chrome — good. But provider names use .headline, the exact size of the "Claude"/"Codex" card titles, so spend reads as a peer, not a footnote. Drop names to .subheadline, hoist the repeated period to the header, let the dollar be the one bold thing.
Does the widget hierarchy keep quota primary and spend secondary?
Large yes, medium no
Large already nests spend as a flat section below the elevated quota tiles — a clean signal. Medium's strip has no divider and competes with the footer. Both surfaces also over-repeat "Current month" and freshness; hoist period once, trust the footer for freshness.

03

Medium widget · one design, two states

The chosen medium widget in both states. Note: the iOS medium carries a "Usage" header the macOS medium doesn't, so on iPhone this layout is tighter than the original preview implied. When API spend is configured it folds into a hairline-separated bottom row (quota stays primary). When it isn't — which is common — the widget is usage-only: the meters center in the frame and the from Mac · 4 min ago stamp holds the bottom-right corner, so a pure-usage widget never looks top-heavy. In every state the freshness stamp is pinned bottom-right, exactly as it is today.

State copy · standardize the four dialects

"No data" and "stale" are currently phrased differently on every surface. One vocabulary, keyed off freshness — and let the amount slot show a real placeholder instead of an action phrase.

06

Implementation punch-list

Everything above, mapped to files. All view-layer + one shared formatter — no model or sync-contract changes, no new iOS controls.

iPhone tile — APISpendMirrorView.swift

  • P1Header becomes an HStack: "API Spend" label + trailing period; drop per-row periodLabel.
  • P1Row name .headline → .subheadline.weight(.semibold); amount stays .title3 mono.
  • P2Amount fallback "Managed on Mac" → "—"; let statusLine carry the reason.

Medium widgets — HeadroomMediumWidgetView + HeadroomIOSWidgetView

  • P1Replace the WidgetAPISpendCompactRow+footer stack with one hairline-separated meta-row (spend left, freshness right) pinned to the bottom.
  • P1Usage-only state (no spend): wrap the columns in Spacer()…columns…Spacer() so they center, footer pinned bottom-right — don't top-align. Fixes the top-weighting.
  • P2Drop the "API" prefix and "from Mac ·" words in the spend row; marks + $ + "4 min ago" carry it.
  • P2Verify both states fit the iOS medium's extra header line at largest Dynamic Type.

Large widgets — WidgetAPISpendView (Section) + iOS mirror

  • P1Section header gains a trailing period; detailText returns "" for fresh/live rows.
  • P2Keep the per-row status line only for stale / needs-setup states.

Shared copy — APISpendPresentation.swift

  • P1statusText: stale-transient returns "Updated {relative}" from capturedAt, not "Stale".
  • P2Standardize the needs-setup string to "Set up on Mac"; align the macOS APISpendSectionView "Add key" button copy or leave it (it's the one surface with a real control).

Out of scope by design: no API-key entry, no period picker, no provider toggles on iOS — all four stay Mac-only, exactly as the PR intends. The macOS Settings/popover "Add key" button is the single legitimate control and stays put.
